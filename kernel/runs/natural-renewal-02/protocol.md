# Untreated copying-role renewal: fixed follow-up

**Cohort.** Run exactly 5,300 new untreated worlds, seeds 100001–105300 inclusive in ascending order, in 53 consecutive batches of 100. The recruitment target is **29 distinct starter-bearing worlds**, not 29 copy events. No early stopping, extension, or seed replacement, regardless of starts, renewals, stagnation or extinction. Batching is operational only. A pre-primary check found no overlap with earlier kernel protocol seed lists or tabulated seed ledgers; natural-renewal-01 used 26689–27712 and the latest earlier kernel primary range was 32001–32032.

**Observation.** Use the [original field and definitions](../natural-renewal-01/protocol.md) unchanged: one `R..CLD` founder at site 36 on the stationary 16 × 4 torus, first-free placement, retained bytes, age limit 80, neighbor reads, local fetch, and 20,000 ppm copy substitutions; no supplied partner or transport. Enroll through tick 8192 inclusive; each enrolled reader gets 324 ticks from its **birth**, not from its starting copy. Observe through tick 8516 and retain the 81-tick tail only to complete lifetime assays; it cannot contribute new scored events. Keep all original checks, hashes, contacts, and status rules. Pre-start extinction remains in the all-world denominator; a starter-bearing world that goes extinct without renewal is a conditional failure.

**Scoring.** Use the original broad confirmed-reader screen as primary and retain the changed-reader screen as descriptive. A start is a confirmed reader's committed birth of a confirmed child from six aligned, unchanged bytes read from a distinct living carrier of its own sequence. The original classifier scores depth one only when two distinct, later-born confirmed descendants replace both roles and every read occurs strictly after both previous participants die. Same-sequence ancestry and the preceding-child path are required as in the original protocol. Depth two or higher is repeated renewal; a complete write without division is not a birth.

**Inference.** Report start incidence, world incidence of at least one renewal, and incidence of renewal conditional on a start, with worlds as independent units. Report repeated renewal (depth ≥ 2) separately; one renewal demonstrates turnover once, not repeated persistence or a population effect. Keep multiple starts and maximal chains without treating them as independent trials. For zero events in `n > 0` worlds, report the one-sided exact 95% binomial upper bound `1 − 0.05^(1/n)`, using 5,300 for world incidence and the **actual** starter-world count for conditional incidence. If none start, the conditional incidence and bound are undefined. If fewer than 29 start and none renew, report the realized bound and mark the conditional 10% target unresolved. Neither pooling with historical worlds nor using the archive as a pooled prior is allowed; historical data only informed planning and validation.

**Reproducibility.** The [pre-primary manifest](revision.sha256) pins the protocol, driver, current VM, historical field and classifier sources, and validation inputs. The generated field replaces only the historical binary seed guard. Validation uses archived starters 26720 and 27266, reproducing nonstarter 26757 (with a recorded contact census), and extinction 27319; compare all six archived tables byte for byte (uncompressed for nodes) with forward `-O2` and reverse `-O3` on the current VM. Run the reference and field tests, original archived positive/negative classifier branches, and synthetic recursion and rejection controls. Validation is excluded from primary denominators and must pass on the frozen inputs before primary execution.

Publish each batch directory by atomic rename only after scoring and verifying its frozen-input and output digests and seed ledgers. The tables preserve world ledgers, raw sparse nodes, contacts, changed readers, starts with chains, and endpoints. An interrupted unpublished batch is rerun with the same seeds; an existing unverifiable batch stops the driver and must be moved aside before replay. The first-batch invocation does not change the fixed cohort or permit any change based on its outcomes.
